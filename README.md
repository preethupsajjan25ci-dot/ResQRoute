# ResQRoute — Emergency Ambulance Tracking & Smart Allocation

A starter capstone project with a Python/FastAPI backend and Flutter mobile client. The prototype can create synthetic emergency requests, filter ambulances by availability and required capabilities, rank eligible vehicles by estimated travel time, display map markers/routes, and let a dispatcher approve an assignment and update its status.

> **Safety note:** This is an educational prototype, not a real emergency dispatch service. Seeded locations and requests are synthetic. Do not use it for real emergencies, patient-care decisions, or actual vehicle dispatch.

## 1. Run the Python backend (Windows)

Install Python 3.10 or later. VS Code is recommended.

1. Extract the ZIP.
2. Open the extracted `resqroute_project` folder in VS Code.
3. Open Terminal → New Terminal.
4. Run:

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

If PowerShell blocks environment activation, run the commands in Command Prompt using `backend\\run_backend.bat`, or skip activation and use `.venv\\Scripts\\python.exe -m pip install -r requirements.txt` and `.venv\\Scripts\\python.exe -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`.

On macOS/Linux, from the project root:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

On first startup, the backend creates `backend/resqroute.db` and seeds synthetic demo ambulances and one pending demo request. The database file is generated at runtime and is not required in the ZIP.

Check these addresses in a browser:

- API health: <http://127.0.0.1:8000/health>
- Interactive API documentation: <http://127.0.0.1:8000/docs>
- Dashboard summary: <http://127.0.0.1:8000/dashboard/summary>

Keep the backend terminal running while using the mobile app.

## 2. Generate a runnable Flutter app (Windows)

The ZIP includes the Flutter client source; platform scaffolding (Android Gradle files, etc.) is generated by Flutter on your computer.

1. Install the Flutter SDK and Android Studio, and make sure `flutter doctor` runs successfully.
2. From the extracted project root, double-click `setup_flutter_windows.bat`, or run it from Command Prompt. The script also enables local HTTP traffic in the generated Android manifest for development on your computer/network only.
3. The script creates a full Flutter project at `resqroute_mobile/`, copies the provided `pubspec.yaml` and `lib/main.dart` over the generated starter files, then runs `flutter pub get`.
4. Open `resqroute_mobile/` in VS Code, start an Android emulator, and run `flutter run`.

Manual alternative if you prefer not to use the script:

```powershell
flutter create --platforms=android --org com.resqroute resqroute_mobile
Copy-Item .\mobile-source\pubspec.yaml .\resqroute_mobile\pubspec.yaml -Force
Copy-Item .\mobile-source\lib\main.dart .\resqroute_mobile\lib\main.dart -Force
cd resqroute_mobile
flutter pub get
flutter run
```

### Backend URL

- **Android emulator:** default `http://10.0.2.2:8000` is correct when backend is running on the same computer.
- **Physical Android phone:** connect the phone and computer to the same Wi-Fi, run backend on `0.0.0.0:8000`, and use your computer's local IPv4 address, for example:

```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.1.25:8000
```

Replace `192.168.1.25` with your computer's actual LAN IP. Allow port 8000 through the local firewall only on a trusted development network. Do not expose this prototype publicly.

## 3. Try the demo workflow

1. Start the backend.
2. Open `/docs` and check that `GET /ambulances` returns synthetic vehicles.
3. Run the Flutter app.
4. Home shows counts and the seeded demo request.
5. Request creates another synthetic emergency using latitude/longitude coordinates.
6. Allocate → select a pending request → **Find eligible ambulances**.
7. Review candidates, tap **View route**, then **Approve** to assign one.
8. Update the active assignment through En route → On scene → Start transport → Complete.
9. Return to Home or Fleet and refresh to see updated counts and statuses.

If the public OSRM demo service cannot be reached, the backend returns an `approximate_fallback` result based on straight-line distance and an assumed speed. The app labels this fallback; it is not a road route and must not be interpreted as a reliable travel-time estimate. OSRM and public map tiles have service policies and usage limits; do not treat public demo services as production infrastructure.

## 4. Test the allocation logic

From the `backend/` folder with the virtual environment active:

```powershell
pytest -q
```

The tests cover capability filtering and ETA-based ranking. They do not validate medical triage or real-world dispatch outcomes.

## 5. API overview

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Check the API is running |
| `GET` | `/dashboard/summary` | Fleet and request counts |
| `GET` | `/ambulances` | List ambulance records |
| `POST` | `/ambulances` | Add a synthetic ambulance |
| `PATCH` | `/ambulances/{id}/status` | Mark an idle ambulance available/offline |
| `POST` | `/ambulances/{id}/location` | Submit a location update |
| `POST` | `/requests` | Create a request |
| `GET` | `/requests` | List requests |
| `GET` | `/requests/{id}/recommendations` | Filter and rank eligible ambulances |
| `GET` | `/routes?request_id=1&ambulance_id=1` | Retrieve route geometry/metrics |
| `POST` | `/requests/{id}/assign` | Approve a recommended allocation |
| `GET` | `/assignments?active_only=true` | List active assignments |
| `PATCH` | `/assignments/{id}/status` | Move an assignment through its demo lifecycle |

## 6. Important limitations and next steps

- The first version does not implement real authentication, driver accounts, push notifications, background GPS collection, or production database migrations. The Android setup script enables cleartext HTTP for local development only; remove that setting and use HTTPS before any non-local deployment.
- CORS is open for local development; restrict it before deployment.
- The assignment endpoint validates status and equipment but this SQLite demo is not hardened for concurrent production dispatch. Real use would require authenticated roles, stronger transaction/locking guarantees, monitoring, data protection, redundancy, qualified operational workflows and extensive validation.
- Priority is stored for display and filtering, but this prototype does not determine clinical severity or automatically triage patients. The ETA rank is only a suggestion for a human dispatcher.
- Coordinates and requests are synthetic. Never add real patient details to the demo.

Suggested capstone evaluation: compare nearest-eligible ambulance vs ETA-based ranking vs a multi-request allocation heuristic using repeatable synthetic scenarios. Measure median/mean ETA, total distance, assignment rate and utilisation. Describe the scenario generator and limitations in the report.
